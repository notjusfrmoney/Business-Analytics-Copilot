# Architecture

Business Analytics Copilot is a small Python application that combines a Streamlit UI, a bounded analytics workflow, SQL validation, and DuckDB. The UI and Python entry points reuse the same query and analysis services.

## Request lifecycle

```text
CSV/XLSX upload
      │
      ▼
normalize columns → validate files → profile schema → session-scoped DuckDB
                                                 │
Natural-language question ──────────────────────┘
      │
      ▼
planner (available schema)
      │
      ├─ for each bounded analysis goal:
      │    SQL generation (question, goal, schema, compact prior results)
      │    → SQLValidator (read-only checks, known tables, DuckDB EXPLAIN)
      │    → DuckDB execution → pandas DataFrame
      │
      ▼
compact evidence summaries → answer generation → evidence verification
      │
      └─ answer, supporting tables, charts, SQL, and trace in Streamlit
```

The workflow is deliberately bounded to four analysis steps by default. A failed follow-up stops further queries; usable earlier evidence is retained. The answer verifier checks claims against the available query evidence and uses a conservative fallback when verification does not pass. These safeguards reduce unsupported claims but do not prove that a business explanation is causal.

## Components

| Component | Responsibility |
| --- | --- |
| `app.py` | Streamlit upload/chat flow, session state, results, charts, and trace. |
| `src/ui/data_loader.py` | Reads CSV/XLSX uploads, normalizes names, validates inputs, and loads tables. |
| `src/database/duckdb_manager.py` | Opens DuckDB and provides schema, table, load, and DataFrame query operations. |
| `src/analytics/query_service.py` | Retrieves the active schema and metadata, generates SQL, validates it, and executes it. |
| `src/analytics/sql_validator.py` | Allows one read-only `SELECT`/`WITH` statement, rejects disallowed operations, checks known table references, and optionally asks DuckDB to `EXPLAIN` it. |
| `src/analytics/planner.py` | Creates a schema-grounded, bounded analysis plan. |
| `src/analytics/analysis_agent.py` | Executes the planned steps and assembles their evidence and trace. |
| `src/analytics/answer_generator.py` | Produces the final answer and checks its factual claims against evidence. |
| `src/llm/client.py` | Sends requests to the configured OpenRouter-compatible chat-completions endpoint. |
| `src/utils/config.py` | Loads configuration from process environment / `.env`, then Streamlit secrets. |
| `evaluation/run_evaluation.py` | Runs deterministic no-network evaluation fixtures against trusted SQL results. |

## Data and model boundaries

The supplied demonstration data is synthetic and consists of:

- `orders`: 2,200 order records from 2023–2024.
- `customers`: 150 customer records.
- `products`: 12 products.
- `targets`: monthly regional target records.

Logical joins are `orders.customer_id → customers.customer_id` and `orders.product_id → products.product_id`. Schema and compact metadata are supplied for planning and SQL generation; the full database is not included in prompts. Bounded result samples and summaries may be sent for follow-up analysis and final answer generation. Requests go to OpenRouter; no model runs locally.

Uploaded files are stored in a DuckDB file associated with the browser session under `data/processed/ui_sessions/`. **Clear data and reset session** removes that session's database. On Community Cloud, the writable local filesystem is ephemeral; it is not persistent or shared storage. No authentication, authorization, or tenant isolation suitable for sensitive production data is provided.

## Safety and limitations

- SQL generated by the model is not executed until the existing validator accepts it.
- The validator is a pragmatic application guard, not a complete SQL security framework or a substitute for process/database isolation.
- Dataset uploads are parsed and queried by the app; only use files suitable for the chosen local or hosted environment.
- Evidence verification checks answer claims against query outputs but cannot establish causal relationships from observational data.
- The deterministic evaluation uses controlled fixtures and synthetic data. Its scores are not live-model quality measurements.

## Configuration

`src/utils/config.py` supports `OPENROUTER_API_KEY`, `OPENROUTER_MODEL`, and `OPENROUTER_BASE_URL`. Non-empty process environment values (including values loaded from local `.env`) take precedence; absent values are read from `st.secrets`. The default API URL is `https://openrouter.ai/api/v1`. A missing local Streamlit secrets file is handled for command-line and test use; malformed secrets configuration is not silently ignored.

See the [demo and deployment guide](demo.md) for local and Community Cloud setup.
